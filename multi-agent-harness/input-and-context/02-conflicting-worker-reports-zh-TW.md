# 兩位 Worker 查到不同結果，下一位該相信哪一份？

[English](./02-conflicting-worker-reports.md) | [繁體中文](./02-conflicting-worker-reports-zh-TW.md) | [简体中文](./02-conflicting-worker-reports-zh-CN.md)

Worker A 在共享筆記寫下「版本 B 的台灣地址測試通過」。稍後，Worker B 回信說「同一版在訂單匯入時仍會拒絕台灣地址」，還附了失敗紀錄。接手寫報告的 Worker C 若直接採用較晚的回信，會漏掉已經驗過的修正。若照抄共享筆記，使用者又會以為匯入也通過了。

沿用前一篇的地址案例，假設原 Task 的驗收條件是「地址驗證函式能接受原先被拒絕的那筆台灣地址」，門牌是 `12號`。C 沿著 A 筆記裡的連結和 B 回信的附件，確認兩人測的是同一個 revision。接著要看的是，兩人把哪筆地址送進哪個入口，又在哪一步看到結果。

| 測試輸入 | A 的紀錄 | B 的紀錄 | C 可以寫進報告的結論 |
|---|---|---|---|
| 一般門牌 `12號` | A1 直接呼叫地址驗證函式，函式接受這筆地址。 | B1 從訂單匯入同一筆地址，匯入回報地址無效。 | 版本 B 的函式接受這筆輸入，匯入流程仍拒絕它。兩項觀察都保留，匯入失敗的原因待查。 |
| 含連字號的門牌 `12-1號` | A2 透過訂單匯入，成功建立測試訂單。 | B2 使用同一份匯入檔，系統回報地址無效。 | 兩筆都測匯入。紀錄裡的 revision、輸入檔和地區設定也相同，這個案例的結果仍待確認。 |

A1 直接回答了原 Task 的驗收問題，C 可以把它交給協調者，並在報告中另列 B1。B1 記下的是匯入畫面回傳「地址無效」。單憑這個訊息，C 還無法判定是哪一步拒絕了地址。下一位調查者可以從 B1 的匯入檔查起，核對匯入流程實際傳給驗證函式的值。若要動手修改匯入模組，仍要另行確認交辦範圍。[另一位 Worker 的回信，能改變我的任務嗎？](./01-peer-replies-and-task-scope-zh-TW.md)

## 哪一筆值得重跑？

A2 和 B2 都走訂單匯入，這時才值得為 `12-1號` 安排重測。如果 B 的回信只寫「同一份檔案」，附件卻只有錯誤畫面，C 應先請 B 補上當時用的檔案或可供比對的檔案雜湊。在取得之前，筆記可先寫「B2 回報匯入遭拒，輸入檔待核對」。只靠門牌相同，還不能認定整筆輸入一致。

在表中的案例，C 已經比對過兩份匯入檔，便可請協調者安排驗證者重跑這一筆。驗證者在乾淨的測試工作區檢出版本 B，使用留存的匯入檔，在與原紀錄相同的地區設定下執行，並記下當次實際載入的設定、匯入回應及是否建立訂單。若再次遭拒，便有一份可供追查的重現紀錄。若成功建立訂單，這次成功也應記下，B2 當時為何遭拒仍待查明。

## 共享筆記怎麼留給下一位 Worker？

在重測結果回來前，C 就能把共享筆記原來的「台灣地址測試通過」改得更精確。本例的 A1、B1、A2、B2 都指向各自的原始測試紀錄。

> 版本 B，台灣地址。原 Task 指定的 `12號` 函式測試已通過（A1）。同一筆地址走訂單匯入時遭拒（B1）。另有一筆 `12-1號` 匯入測試，A2 建立了訂單，B2 回報地址無效。兩次使用相同的匯入檔，結果有出入，待驗證者重測。

假設驗證者回報這次成功建立訂單，C 可以在 A2、B2 旁補一句「同檔在版本 B 重測後建立訂單，執行設定與結果見重測紀錄 R1。B2 遭拒的原因待查」。下一位 Worker 若要查那次失敗，仍找得到 B2 的原始回應；協調者若只要驗收地址函式，也知道該看 A1。

若實作者後來交出版本 C，這段筆記仍能當作版本 B 的比較依據。接手者可以沿用輸入檔與測試步驟，在 C 上另記結果，讓協調者看得出這次交付實際驗了哪些案例。[要求改了，哪些委派還有效？](../foundations/04-revising-delegated-work-zh-TW.md)
